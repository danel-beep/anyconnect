# Manyplug

Один облачный MCP-хаб для всех ваших сервисов и аккаунтов. Подключаете хаб к ChatGPT, Claude
или другому ИИ-клиенту один раз, а дальше ИИ видит всё, что подключено к хабу, в том числе
сервисы без своего MCP и **несколько аккаунтов одного сервиса** (две почты, два Telegram и т.д.).

```
ChatGPT / Claude / Claude Code / Cursor
            │  MCP по HTTPS + OAuth 2.1
            ▼
   ┌───────────────────── Manyplug ─────────────────────┐
   │  OAuth-сервер · MCP-эндпоинт · каталог инструментов   │
   │  коннекторы:  gmail(work, personal) · telegram(main,  │
   │               shop) · любой API · любой MCP ...        │
   │  Postgres: аккаунты, зашифрованные ключи, аудит        │
   └───────────────────────────────────────────────────────┘
```

## Что уже есть (этап 1: фундамент)

- **Удалённый MCP-сервер** (`/mcp`) на официальном SDK v2: спецификация 2026-07-28 и
  обратная совместимость с клиентами 2025 года (сегодняшние Claude и ChatGPT). Работает без
  состояния, поэтому деплой не обрывает подключения и можно запускать несколько инстансов.
- **Свой OAuth 2.1 сервер** под требования Claude и ChatGPT: PKCE (S256), Client ID Metadata
  Documents и Dynamic Client Registration, RFC 8707 (токены привязаны к адресу хаба), RFC 9207
  (`iss`), ротация refresh-токенов с обнаружением повторного использования, отзыв доступа.
- **Мультиаккаунтность в основе модели данных**: сервис → много именованных аккаунтов. ИИ видит
  инструмент `gmail_search` с аргументом `account: "work" | "personal"` (или, по настройке,
  отдельные инструменты на каждый аккаунт). Читающие инструменты по умолчанию работают сразу по
  всем аккаунтам (`account: "all"`), а единые инструменты (`mail_search`, `messages_send`…)
  охватывают все почтовые ящики или мессенджеры одним вызовом.
- **Экономия контекста ИИ**: пока инструменты помещаются в ~3000 токенов, они показываются все;
  дальше хаб сам переходит в режим поиска (`manyplug_search_tools` / `call_tool`) и показывает
  только самые нужные. `manyplug_call_tools` выполняет до 10 вызовов за один шаг.
- **Подключаемые коннекторы**: новый сервис = один файл с zod-схемами. Хаб сам делает
  маршрутизацию по аккаунтам, шифрование, таймауты, ошибки и аудит.
- **Шифрование ключей** сервисов: у каждого аккаунта свой ключ (AES-256-GCM), он зашифрован
  мастер-ключом из переменной окружения; ротация мастер-ключа без перешифровки данных.
- **Кто что может**: правила «ИИ-клиент × аккаунт × риск» (например, ChatGPT только читает
  почту, Claude может отправлять), персоны со своим адресом MCP (`/mcp/work` видит только рабочие
  аккаунты).
- **Подтверждение опасных действий**: прямо в чате (MCP elicitation), кнопками в Telegram или
  по ссылке; окно отмены для отправки. Тексты писем и сообщений помечаются как данные, а не
  команды (защита от prompt injection).
- **Двухфакторный вход**: приложение-аутентификатор (TOTP), passkey (Face ID, Touch ID,
  Windows Hello, аппаратные ключи; можно входить и без пароля), коды восстановления. Настройка —
  на странице «Безопасность» (`/security`); `REQUIRE_2FA=true` делает второй фактор обязательным.
- **Настройка из чата**: после одного подключения хаба всё остальное делается из Claude или
  ChatGPT. Инструменты `manyplug_*` показывают доступные сервисы, выдают ссылку для подключения
  аккаунта (пароли и ключи никогда не проходят через чат), переименовывают аккаунты, скрывают
  инструменты, меняют режим списка. Удаление и добавление внешнего сервиса всегда подтверждает
  пользователь.
- **Учёт использования** по аккаунту нейросети, а не по почте: ChatGPT сообщает, какой его
  пользователь звонит (хранится только хэш), для Claude счёт идёт по подключению приложения.
  `GET /api/v1/usage`. На этапе 1 только считает, ничего не ограничивает.
- Страницы входа и согласия (RU/EN), главная страница с адресом MCP и списком подключений,
  REST API `/api/v1`, CLI, личные токены для клиентов со статическими заголовками.
- **Telegram и WhatsApp**: боты Telegram (Bot API) и номера WhatsApp Business (Cloud API)
  подключаются как обычные аккаунты, переписка хранится в хабе зашифрованной и ищется
  мгновенно, отправка идёт через очередь с темпом «как человек» и без дублей. Для личного
  Telegram и WhatsApp через официальное приложение есть шлюз постоянных сессий
  (`docs/MESSENGERS.md`).
- Встроенный тестовый сервис **Demo** с двумя аккаунтами, чтобы сразу проверить подключение.
- **Готовые сервисы**: почта IMAP/SMTP (Яндекс, Mail.ru, Gmail, iCloud, любой сервер), Gmail,
  Outlook (почта и календарь), Google Calendar, Google Drive, Slack, Notion, GitHub, Todoist, Stripe
  и любой HTTP API. Как подключить каждый: [docs/SERVICES.md](docs/SERVICES.md).
- Docker, Render Blueprint, CI (lint, типы, больше 350 тестов включая сквозной OAuth через официальный
  MCP-клиент, сборка Docker).

Дальше по плану: личный Telegram и WhatsApp через шлюз → веб-панель → подключение любого API без
программирования (по OpenAPI).

## Быстрый старт локально

Нужны Node.js 22+ и Postgres (проще всего через Docker).

```bash
npm install
docker compose up -d db
cp .env.example .env        # задайте ADMIN_EMAIL и ADMIN_PASSWORD
npm run dev
```

Откройте http://localhost:3000, войдите. На главной странице будет адрес MCP-сервера.
Для локальной проверки с Claude Code:

```bash
claude mcp add --transport http manyplug http://localhost:3000/mcp
```

Claude Code откроет браузер для входа и согласия, после чего увидит инструменты `demo_*`.

## Деплой на Render

1. В Render: **New → Blueprint**, выберите этот репозиторий. Blueprint (`render.yaml`) создаст
   веб-сервис (Docker, план Starter, Франкфурт) и Postgres.
2. Укажите `ADMIN_EMAIL` и `ADMIN_PASSWORD` (пароль от 12 символов).
3. `ENCRYPTION_KEY` сгенерируется сам. **Сохраните его копию**: без него сохранённые ключи
   сервисов не расшифровать.
4. После деплоя адрес будет вида `https://<имя сервиса>-xxxx.onrender.com`. `PUBLIC_URL` указывать
   не нужно: хаб берёт `RENDER_EXTERNAL_URL`.

### Свой домен

1. Render → сервис → **Settings → Custom Domains**: добавьте домен (например `manyplug.com`;
   `www` Render добавит сам и будет перенаправлять на основной).
2. У регистратора: запись `A` для `@` → `216.24.57.1`, `CNAME` для `www` → адрес сервиса
   `<имя>.onrender.com`. Дождитесь в Render статусов **Verified** и сертификата.
3. В Google OAuth-клиенте добавьте адреса возврата на новом домене (см. ниже) и домен в
   **Branding → Authorized domains**.
4. Задайте `PUBLIC_URL=https://<домен>`. Старый адрес `*.onrender.com` дальше перенаправляет на
   новый (301 для страниц, 308 для MCP и OAuth). Другие прежние адреса перечислите в
   `LEGACY_PUBLIC_URLS`.
5. После смены домена ИИ-приложения один раз попросят войти заново (токены привязаны к адресу
   MCP), а passkey нужно добавить заново (они привязаны к домену); код из приложения
   (TOTP) продолжает работать. В настройках ИИ-приложений лучше заменить адрес на новый.

### Вход через Google

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → **Create
   credentials → OAuth client ID → Web application**.
2. **Authorized redirect URIs**: `https://<ваш адрес>/auth/google/callback` (вход на сайт) и
   `https://<ваш адрес>/connect/callback` (подключение Gmail, Календаря, Диска).
3. В Render задайте `LOGIN_GOOGLE_CLIENT_ID` и `LOGIN_GOOGLE_CLIENT_SECRET`. Этот же клиент
   используется и для подключения Gmail, Календаря и Диска, если не заданы отдельные
   `OAUTH_APP_GOOGLE_CLIENT_ID` / `_SECRET`.
4. `SUPPORT_EMAIL` — адрес для вопросов и запросов тарифа, его видно на сайте.

### Оплата

Paddle или Stripe подключаются переменными `BILLING_PROVIDER`, ключами провайдера и ценами
`<PROVIDER>_PRICE_<PLAN>_<MONTH|YEAR>`; без ключей всё можно проверить с
`BILLING_PROVIDER=test`. Пошагово: [docs/BILLING.md](docs/BILLING.md).

### Gmail, Календарь и Диск

1. В том же проекте Google Cloud включите **Gmail API**, **Google Calendar API**, **Google Drive
   API** и **Google Sheets API** (APIs & Services → Library).
2. Google Auth Platform → **Data Access** → добавьте доступы коннекторов:
   `https://www.googleapis.com/auth/gmail.modify`, `https://www.googleapis.com/auth/calendar`,
   `https://www.googleapis.com/auth/drive`, `https://www.googleapis.com/auth/spreadsheets`,
   `https://www.googleapis.com/auth/drive.metadata.readonly`.
3. Пока приложение не прошло проверку Google, при подключении пользователи видят предупреждение
   «Google hasn't verified this app» (Advanced → Go to Manyplug), и подключиться могут не больше
   100 человек. Для себя и первых пользователей этого достаточно.
4. Для открытого запуска нужна проверка в Google Auth Platform → **Verification Center**:
   - Календарь — «чувствительный» доступ: подтверждение домена, политика конфиденциальности,
     объяснение, зачем нужен доступ, и видео, как приложение им пользуется.
   - Gmail и Диск — «ограниченный» доступ: всё то же плюс ежегодная платная проверка безопасности
     (CASA) у одной из лабораторий, которые назначает Google.
   - Домен `*.onrender.com` подтвердить сложнее, чем свой: для проверки лучше подключить свой
     домен (`PUBLIC_URL`) и добавить новые адреса возврата в клиент.

Остальные настройки сайта (`SIGNUPS`, `ADMIN_EMAILS`, `ADMIN_ALLOWED_IPS`, `ADMIN_SESSION_HOURS`,
`TRUST_PROXY`, `GOOGLE_SITE_VERIFICATION`, `BING_SITE_VERIFICATION`) описаны в `.env.example`.
Инструкции для ИИ-клиентов, страницы «сервис × клиент», FAQ, сравнения, sitemap, robots.txt и
llms.txt описаны в [docs/SEO.md](docs/SEO.md).

### Админка

Владелец (`ADMIN_EMAIL`) — администратор. Откройте `/security`, включите приложение-аутентификатор
или passkey, затем `/admin`: без второго фактора админка не откроется. Там пользователи, тарифы,
добавки к лимитам, блокировка, запросы тарифов, журнал действий и проверка настроек сервера
(«Система»).

Бесплатный план Render засыпает через 15 минут простоя, а ИИ-клиенты не ждут холодный старт,
поэтому в Blueprint стоит Starter. Хаб работает и на любой другой платформе с Docker и Postgres.

## Подключение ИИ-клиентов

Адрес MCP: `https://<ваш-хаб>/mcp`. При подключении клиент откроет страницу входа в хаб и
страницу согласия, где видно, какое приложение просит доступ и куда вы вернётесь.

| Клиент | Как подключить |
| --- | --- |
| Claude (web, desktop, mobile) | Настройки → Коннекторы → Добавить свой коннектор → адрес MCP |
| ChatGPT | Настройки → Приложения и коннекторы → Расширенные → Режим разработчика → Создать, аутентификация OAuth |
| Claude Code | `claude mcp add --transport http manyplug https://<хаб>/mcp` |
| Скрипты, клиенты со статическим заголовком | личный токен: `Authorization: Bearer ac_pat_...` |

Подключённые приложения видны на главной странице хаба, доступ можно отозвать одной кнопкой.

После подключения достаточно написать ассистенту «подключи мою почту Gmail»: он вызовет
`manyplug_connect_account` и покажет ссылку, по которой вы войдёте в Google на странице хаба.

Подключение до входа (`MCP_ANONYMOUS=true`, по умолчанию выключено): приложение видит список
сервисов без входа в хаб, а первый вызов, которому нужен аккаунт, получает ответ 401, и
приложение открывает страницу входа. Запросы без входа ограничены
`MCP_ANONYMOUS_RATE_LIMIT` в минуту с одного IP. Выключено по умолчанию, потому что часть
приложений определяет, нужен ли вход, по первому ответу сервера: если он 200, такое приложение
подключится без входа и не покажет кнопку входа.

Персоны: если создать персону `work` (`POST /api/v1/personas`), у неё будет свой адрес
`https://<хаб>/mcp/work` — подключённый к нему клиент видит только её аккаунты.

Подтверждения в Telegram: создайте бота у @BotFather, задайте `TELEGRAM_BOT_TOKEN` и откройте
в хабе страницу «Подтверждения» → «Привязать Telegram».

## Управление аккаунтами (до веб-панели)

CLI выбирает пользователя из `ADMIN_EMAIL`. Локально: `npm run cli -- <команда>`, в Shell на
Render (в собранном образе): `node dist/cli/index.js <команда>`.

```bash
npm run cli -- connectors:list
npm run cli -- accounts:add --connector demo --label "Третий аккаунт" --credentials '{"secret":"x"}'
npm run cli -- accounts:list
npm run cli -- tools:list                      # что именно видит ИИ
npm run cli -- exposure:set --mode per_account # отдельный инструмент на каждый аккаунт
npm run cli -- tokens:create --name "laptop" --api  # личный токен: MCP, с --api ещё и REST API
npm run cli -- users:2fa:reset --email you@example.com  # потерян телефон: сбросить второй фактор
```

REST API (`Authorization: Bearer ac_pat_...`). Нужен токен со scope `api`: по умолчанию токены
(в кабинете, CLI и `POST /api/v1/tokens`) работают только с MCP, а API управления включается
явно (`--api`, галочка в кабинете, `"scopes": ["mcp", "api"]`). Токен с `api` может менять
аккаунты, правила и настройки безопасности, поэтому его не отдают AI-приложению: иначе оно
смогло бы ослабить свои же правила. Токен профиля доступа (`personaId`) работает только с MCP.

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/v1/connectors` | сервисы и JSON-схемы их настроек и ключей |
| GET/POST | `/api/v1/accounts` | список / добавить аккаунт (ключи шифруются, наружу не отдаются) |
| GET/PATCH/DELETE | `/api/v1/accounts/:id` | аккаунт: переименовать, выключить, скрыть действия, сменить ключи |
| POST | `/api/v1/accounts/:id/test` | проверить подключение |
| POST | `/api/v1/connect` | начать подключение аккаунта через OAuth, ответ — `authorizationUrl` |
| GET | `/api/v1/oauth/providers` | OAuth-провайдеры, redirect URI для их консолей, настроенные приложения |
| GET/POST/DELETE | `/api/v1/oauth/apps[/:id]` | свои OAuth-приложения (client id + secret) |
| GET/POST/PATCH/DELETE | `/api/v1/services[/:id]` | свои сервисы без кода: внешние MCP-серверы и HTTP-манифесты |
| POST | `/api/v1/services/:id/refresh` | обновить список инструментов внешнего MCP-сервера |
| GET | `/api/v1/tools` | инструменты так, как их видит ИИ |
| POST | `/api/v1/tools/:name/call` | вызвать инструмент (для отладки) |
| GET/DELETE | `/api/v1/grants[/:id]` | подключённые ИИ-приложения |
| GET/POST/DELETE | `/api/v1/tokens[/:id]` | личные токены |
| GET | `/api/v1/tool-calls` | журнал вызовов |
| PATCH | `/api/v1/workspace` | настройки, например `{"settings":{"toolExposure":"per_account"}}` |

### Подключение через OAuth (Google, Microsoft, Slack, Notion, GitHub, Todoist…)

1. Зарегистрируйте OAuth-приложение у провайдера с redirect URI `https://<хаб>/connect/callback`
   (один адрес на все сервисы; точный адрес — в `GET /api/v1/oauth/providers`).
2. Передайте его хабу: переменными окружения `OAUTH_APP_GOOGLE_CLIENT_ID` /
   `OAUTH_APP_GOOGLE_CLIENT_SECRET` (для всего хаба) или через `POST /api/v1/oauth/apps`
   (своё приложение в пространстве, секрет шифруется).
3. Откройте в браузере `https://<хаб>/connect/<сервис>?label=Рабочая` и разрешите доступ. Аккаунт
   появится с адресом почты из проверки подключения. Повторное подключение того же аккаунта:
   `/connect/<сервис>?account=<id>`.

Дальше хаб сам обновляет токены (заранее, фоновой задачей, и при ответе 401), а если провайдер
отозвал доступ, помечает аккаунт «нужно переподключить». Сервисы, где можно обойтись личным токеном
(GitHub, Todoist, Notion, Slack), принимают его в `credentials.token` без OAuth-приложения.

### Подключение по ключу или паролю (IMAP, Stripe, любой HTTP API…)

Та же ссылка `https://<хаб>/connect/<сервис>` у сервисов без OAuth открывает форму: поля строятся
из схем `config` и `credentials` коннектора, ключи и пароли вводятся только на странице хаба и
сразу шифруются. После сохранения хаб проверяет подключение и показывает результат. Для сервисов
с необязательным OAuth форма открывается, пока у хаба нет OAuth-приложения (или с `?via=form`).
Переподключение: `/connect/<сервис>?account=<id>` — пустое поле ключа оставляет сохранённый.
Эту же ссылку выдаёт ассистенту `manyplug_connect_account`.

## Как добавить сервис

### Внешний MCP-сервер без кода

```bash
curl -X POST https://<хаб>/api/v1/services -H "authorization: Bearer ac_pat_..." \
  -H "content-type: application/json" \
  -d '{"kind":"mcp","url":"https://mcp.linear.app/mcp","name":"Linear","id":"linear"}'
```

Хаб сам найдёт OAuth сервера и зарегистрируется у него как клиент; затем откройте
`https://<хаб>/connect/linear` и войдите. Инструменты сервера появятся у ИИ как `linear_…` с
выбором аккаунта. Сервер со статическим ключом: `"auth":"bearer"` и аккаунт с
`credentials.token`.

### Свой коннектор

Подробное руководство — [docs/CONNECTORS.md](docs/CONNECTORS.md). REST-сервисы проще всего
описывать HTTP-манифестом, без кода. Кодовый коннектор описывает сервис и его действия; про MCP,
аккаунты, шифрование и сеть он не знает:

```ts
// src/connectors/builtin/weather.ts
import { z } from 'zod';
import { HttpClient } from '../http/client.js';
import { defineConnector } from '../sdk.js';

export default defineConnector({
  id: 'weather',
  name: 'Weather',
  description: 'Weather forecasts',
  version: '1.0.0',
  credentials: z.object({ apiKey: z.string().describe('API key from the weather provider') }),
  actions: (action) => [
    action({
      name: 'forecast',
      description: 'Forecast for a city for the next days',
      input: z.object({ city: z.string().describe('City name') }),
      hints: { readOnly: true },
      run: async ({ city }, ctx) => {
        // ctx.fetch: сетевая политика хаба; HttpClient сам превращает 401/404/429 в ошибки хаба.
        const api = new HttpClient(ctx, {
          baseUrl: 'https://api.example',
          headers: { authorization: `Bearer ${ctx.credentials.apiKey}` },
        });
        return (await api.get('/forecast', { q: city })).data;
      },
    }),
  ],
});
```

Затем зарегистрируйте его в `src/connectors/index.ts`. ИИ сразу получит `weather_forecast`
с выбором аккаунта. Уровень риска, отмена, общие интерфейсы (почта, сообщения, календарь…),
лимиты и помощники для компактных ответов описаны в [docs/CONNECTORS.md](docs/CONNECTORS.md).

## Безопасность

- Секреты только в переменных окружения, в репозитории их нет. `.env` в `.gitignore`.
- Ключи сервисов зашифрованы AES-256-GCM и привязаны к аккаунту (скопировать шифротекст в
  другую строку не получится). Через API и ИИ они не возвращаются.
- Токены (OAuth, личные, сессии) хранятся только как SHA-256-хэши.
- Страница согласия защищена от встраивания во фрейм, формы — CSRF-токеном и проверкой Origin,
  вход — ограничением попыток. Загрузка внешних метаданных клиентов защищена от SSRF.
- Второй фактор: TOTP (секрет зашифрован, повтор кода отклоняется), passkey (WebAuthn, challenge
  одноразовые и хранятся на сервере), 10 одноразовых кодов восстановления (только хэши). Пока
  второй фактор не подтверждён, сессия не создаётся. Изменение настроек безопасности требует
  входа не старше 10 минут. Подробнее — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#вход-и-второй-фактор).
- Ошибки коннекторов не раскрывают внутренние детали ИИ-клиенту; аргументы вызовов не логируются.
- Правила доступа проверяются и при показе инструментов, и при каждом вызове; рискованные
  действия ждут подтверждения пользователя, которое не может дать ни один токен. Подробнее — в
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#защита-данных).
