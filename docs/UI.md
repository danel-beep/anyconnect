# Вёрстка: контракт разметки и стилей

Сайт, кабинет и админ-панель — серверный JSX (Hono) и один общий CSS из `src/web/styles.ts` и
`src/web/styles/*.ts`, цвета — токенами из `src/web/theme.ts` (см. «Оформление веб-панели» в
[ARCHITECTURE.md](ARCHITECTURE.md)). Этот документ — правила, которые не дают вёрстке «поплыть».

## Почему вёрстка плывёт

Почти всегда причина одна из трёх, и ни одна не видна в обычных тестах: страница отдаёт 200,
текст на месте.

1. **Класс, который ничего не стилизует.** Опечатка, модификатор без базового класса
   (`pad` без `card-head`), класс, переименованный в CSS, или правило, написанное для `ul`, а
   применённое к `ol`. Блок молча теряет отступы, сетку или рамку.
2. **Атрибут `style`.** CSP сайта — `style-src 'self'`, браузер в продакшене выбрасывает
   inline-стили. Локально в тесте страница выглядит правильно, на сайте — нет.
3. **Режим совместимости (quirks mode)** без `<!doctype html>`: другая модель блоков и высот
   строк. Doctype выводит `Layout`/`SiteLayout`, свои HTML-ответы в обход них не собираются.

## Контракт (`test/ui-contract.test.ts`)

Тест читает все `src/**/*.tsx` и весь `APP_CSS` без браузера, за доли секунды, и падает, если:

- **у элемента есть класс, который стилизует ничто на этом элементе.** Класс считается
  стилизованным, если в CSS есть селектор, где он стоит в одной связке (compound) с тегом и
  классами, которые у элемента действительно есть. `.card-head.pad` стилизует
  `<div class="card-head pad">`, но не `<p class="pad">`; `ul.plain>li` не стилизует `<ol class="plain">`;
- **у HTML-элемента есть атрибут `style`.**

Плюс самопроверка сканера: если он вдруг перестанет находить элементы, тест тоже упадёт.

Ошибка выглядит так: `src/web/team.tsx:33 <p> class "pad"`. Чинится разметкой или CSS, **никогда
не исключением в тесте**:

| Что случилось | Как чинить |
| --- | --- |
| Класс не нужен (стилей не было и не задумывалось) | Убрать класс |
| Задумывался вид, но правила нет | Добавить правило в CSS — и проверить страницу глазами |
| Модификатор без базы (`pad` без `card-head`) | Взять готовый компонент из `src/web/ui.tsx` или правило под эту связку |
| Правило под другой тег (`ul.plain` на `<ol>`) | Расширить селектор (`ul.plain,ol.plain`) |
| Нужен inline-стиль | Класс или модификатор в CSS; для значений — заранее заданная шкала (`heat-0…heat-5`, `pctClass()`) |
| Класс нужен только скрипту или тесту | Атрибут `data-*` или `id`: классы — только для оформления (соглашение, тест его не проверяет; старые скрипты и тесты ещё ищут по классам) |

## Что сканер понимает

- Статические классы: `class="card flush"`.
- Выражения: ``class={`dot ${ok ? 'ok' : 'bad'}`}`` — проверяются `dot`, `ok`, `bad`.
- Префиксы: ``class={`heat-${level}`}`` — нужен хотя бы один класс CSS, начинающийся с `heat-`.
- Аргументы вызовов (`pctClass('w', used, max)`) и сравниваемые значения (`plan === 'free'`) —
  данные, а не классы, их сканер пропускает.
- CSS: вложенные `@media`/`@supports`/`@container`/`@layer`, `:is()`/`:where()` (раскрываются),
  `:not()` и псевдоклассы (отбрасываются), аргументы `:has()` (считаются отдельными связками).
- Компоненты (`<Card class=…>`) проверяются по имени класса: что с ним сделает компонент, сканер
  не знает. Поэтому общий вид живёт в компонентах `src/web/ui.tsx`, а не в классах на месте.
- Закомментированная разметка (`{/* … */}`) не проверяется. Самопроверка следит, чтобы каждый
  `class=` в исходниках принадлежал прочитанному элементу: тег, который сканер не разобрал,
  роняет тест, а не выпадает из проверки молча.

### Чего контракт не видит

- Классы из переменных и вызовов: ``class={`notice ${flash.kind}`}`` проверяет только `notice`,
  `cx(...)` и `pctClass(...)` пропускаются. Для префикса (`heat-${x}`) хватает любого класса CSS с
  этим началом.
- Класс, который совпал, но проиграл более специфичному правилу (например, `ul.plain>li` перебивает
  отступы `.pad`). Это ловит только браузер: `npm run test:visual` и взгляд на страницу.
- Класс внутри `:not(...)`/`:has(...)` считается использованным, даже если сам по себе ничего не
  оформляет.

Сам сканер — `test/ui/markup.ts`, его поведение закреплено юнит-тестами в том же файле теста.

## Готовые решения вместо ручных классов

- Строки списка с разделителями: `ul.plain` / `ol.plain`.
- Маркированный или нумерованный текст: `ul.bullets` / `ol.bullets`.
- Готовый текст, который человек вставит в другое место (запрос для ИИ, сообщение коллеге), —
  `CopyText` из `src/web/ui.tsx`; с `prompt` вся карточка — одна кнопка «Копировать».
- Карточки, заголовки страниц, метрики, вкладки, поля копирования — компоненты из `src/web/ui.tsx`
  и `src/web/app.tsx` (`PageHead`, `Meter`, `Tabs`, `CopyField`…).
- Заголовок карточки с иконкой, пояснением и статусом справа — `SectionHead`.
- «Спросите свой ИИ»: блок готовых запросов, которые копируются по нажатию, — `AskAi` (каждый запрос — `CopyText prompt`). Всё, что
  настраивается на сайте, можно сделать и из чата: ставь `AskAi` рядом с такими настройками
  (запросы должны работать с настоящими инструментами `manyplug_*`).

## Порядок работы

1. Меняешь вёрстку — `npm run check:fast` (контракт входит в него при изменении `.tsx` и стилей).
2. Добавил или поменял правило CSS — открой страницу в светлой и тёмной теме, на десктопе и
   телефоне (390 px): контракт ловит «класс без стиля», но не «стиль не тот».
