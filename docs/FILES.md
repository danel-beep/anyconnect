# Файлы между инструментами (`ctx.files`)

ИИ часто нужно взять файл в одном месте и отдать в другом: переслать фото из одного чата Telegram
в другой, отправить вложение из WhatsApp личным аккаунтом, приложить к сообщению картинку, которую
сделал сам. Гонять байты через ИИ (base64 в ответе и снова в аргументах) дорого и ломается на
больших файлах. Поэтому хаб держит у себя короткоживущее хранилище файлов, и инструменты передают
друг другу только `file_id`.

## Как это выглядит для ИИ

1. Инструмент, который достаёт файл (сейчас `get_attachment` любого мессенджера), кладёт его в
   хранилище и пишет в ответе: `To send it on, pass file_id "file_…" to a send tool`.
2. Инструмент, который отправляет файл (сейчас `send` мессенджеров), принимает один из источников:
   `file_url` (https-ссылка), `file_id` или `file_base64` (небольшие файлы, которые ИИ сделал сам),
   плюс `file_name`. Два источника сразу — ошибка.

Поля и их разбор общие: `fileInputFields` и `resolveFileInput` в `src/connectors/file-input.ts`.
Новый инструмент с файлом (вложение письма, загрузка в Drive) берёт их же, а не придумывает свои.
`resolveFileInput` проверяет, что `file_id` есть, а `file_base64` сразу кладёт в хранилище: дальше
(очередь отправки, подтверждение) путешествует только id. Тип файла определяется по первым байтам
(`sniffMime`: JPEG, PNG, GIF, WebP, PDF, MP4, OGG, MP3) или по расширению имени.

## Хранилище (`src/core/files.ts`, таблица `hub_files`)

- Файл принадлежит рабочему пространству: его видят все аккаунты пространства (так фото переходит
  от одного аккаунта к другому), другое пространство — нет. id — `file_` + 80 случайных бит, угадать
  нельзя.
- Шифрование: у каждого файла свой ключ данных, обёрнутый мастер-ключом (AAD — id файла); байты и
  имя зашифрованы, в открытом виде только тип и размер. Байты лежат в `bytea` без base64.
- Срок — 24 часа с последнего `put`. Те же байты, положенные снова, дают тот же id и продлевают
  срок (ключ — HMAC содержимого), поэтому повторная отправка того же файла распознаётся как дубль.
- Лимиты: файл до 20 МБ, живых файлов на пространство до 200 МБ. Пустые файлы не принимаются.
- Задача `files.prune` (каждые 30 минут) удаляет просроченные.
- Для запечатанных аккаунтов (docs/VAULTS.md) копия файла в хранилище защищена мастер-ключом, как
  и переписка мессенджеров, а не ключом сейфа.

Коннектор видит хранилище как `ctx.files` (`HubFiles` в `src/connectors/sdk.ts`): `put`, `get`,
`stat`, `maxBytes`. Где хаб работает без хранилища (некоторые тестовые контексты), `requireFiles`
отвечает понятной ошибкой.

## Мессенджеры

Очередь отправки хранит только ссылку или `file_id`; диспетчер подгружает байты из хранилища прямо
перед отправкой (`Dispatcher.withFile`). Если файл истёк, пока сообщение ждало в очереди, задача
отклоняется с понятной причиной. Подробности по каждому мессенджеру — в
[MESSENGERS.md](MESSENGERS.md), раздел «Файлы».

## Чего пока нет

- Вложения писем по `file_id` (Gmail, Outlook, SMTP) и выдача `file_id` из вложений писем.
- Страница загрузки: файл, который человек прикрепил в чате с ИИ, ИИ передать не может (байты есть
  только у ИИ-клиента). Решение — ссылка на загрузку из хаба, которую ИИ даёт человеку.
- Поля файлов в формате ChatGPT Apps (`openai/fileParams`): ChatGPT сам передаёт ссылку на
  прикреплённый файл, её можно принимать как `file_url`.
