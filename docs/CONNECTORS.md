# Как писать коннекторы

Коннектор описывает один *сервис*. Хаб хранит сколько угодно аккаунтов этого сервиса, превращает
действия в MCP-инструменты, шифрует ключи, ведёт журнал. Есть три способа добавить сервис:

| Способ | Когда | Где |
| --- | --- | --- |
| HTTP-манифест | REST/JSON API (большинство сервисов) | `defineManifestConnector({...})` |
| Код | Нестандартный протокол (IMAP, SMTP), сложная логика | `defineConnector({...})` |
| Внешний MCP | У сервиса уже есть удалённый MCP-сервер (Notion, Linear, Zapier, другой хаб) | `POST /api/v1/services`, см. ниже |

Новый встроенный коннектор регистрируется в `src/connectors/index.ts`. Манифест и внешний MCP можно
добавить и без кода, прямо в пространство через API (раздел «Сервисы без кода»).

## Что коннектор получает в контексте

| Поле | Что это |
| --- | --- |
| `ctx.account` | Какой аккаунт обслуживается (`id`, `name`, `label`, `identity`). |
| `ctx.config`, `ctx.credentials` | Настройки и расшифрованные ключи этого аккаунта, уже проверенные схемой. Из этих же схем хаб строит форму подключения `/connect/<сервис>` (`core/connect-form.ts`): `.describe()` становится подсказкой под полем, поля `credentials` — полями пароля, `enum` — списком; подписи на языке сайта и раскладку формы задаёт `ui` (см. «Тексты для сайта и форма подключения»). |
| `ctx.fetch` | Единственный разрешённый HTTP-транспорт. Хаб подставляет транспорт с сетевой политикой, тесты подставляют фикстуры. Глобальный `fetch` в коннекторах не используем. |
| `ctx.network.lookup` | DNS-lookup с той же политикой для библиотек на сокетах (`net`, `tls`, `imapflow`, `nodemailer`, `pg`). Для хоста-IP перед подключением вызвать `ctx.network.assertHostAllowed(host)`: библиотеки не зовут `lookup` для IP-адресов. |
| `ctx.oauth` | Для OAuth-сервисов: свежий `accessToken` (хаб обновляет его сам), `refresh()` для повтора после 401, `extra` (несекретные поля ответа, например команда Slack). |
| `ctx.signal` | Отмена вызова клиентом или таймаут. Передавать во все запросы. |

**Сетевая политика.** В облаке коннекторы не могут ходить на приватные адреса (метаданные облака,
база, внутренние сервисы). Проверка идёт в момент соединения, поэтому её не обходят ни редиректы,
ни DNS-rebinding, ни IP в адресе. `ALLOW_PRIVATE_NETWORK=true` снимает ограничение (локальная
разработка, сервисы в домашней сети); в облаке не включать.

## HTTP-клиент

`new HttpClient(ctx, { baseUrl, headers, errorMessagePaths, rateLimit })` из
`src/connectors/http/client.ts` — общий клиент для кодовых коннекторов и движка манифестов:

- ходит через `ctx.fetch` с `ctx.signal`, добавляет OAuth-токен и при 401 один раз обновляет его;
- ошибки сервиса превращает в `ConnectorError`: 401 → `auth` (аккаунт помечается «переподключить»),
  403 → `permission`, 404 → `not_found`, 429 → `rate_limited` с `Retry-After`, прочие 4xx →
  `invalid_input`, 5xx → `upstream`; текст ошибки берётся из ответа сервиса (HTML-страницы ИИ не
  показываются);
- повторяет идемпотентные запросы один раз при 502/503/504 и сетевых сбоях, короткие 429 пережидает;
- лимит частоты на аккаунт (token bucket): короткое ожидание поглощается, длинное возвращается ИИ
  как «повторите через N секунд».

## HTTP-манифест

Манифест — обычные данные (JSON-совместимые), поэтому тот же формат пойдёт для сервисов без кода
из базы, коннекторов из OpenAPI (этап 4) и составных инструментов. Схема: `src/connectors/manifest/schema.ts`.

```ts
import { defineManifestConnector } from '../manifest/compile.js';

export default defineManifestConnector({
  id: 'tracker',
  name: 'Tasks',
  description: 'Трекер задач',
  baseUrl: 'https://{{config.region}}.tasks.example/api/v1',
  config: { type: 'object', properties: { region: { type: 'string', default: 'eu' } } },
  auth: { type: 'api_key', in: 'header', name: 'X-Api-Key' }, // ключ: credentials.apiKey
  headers: { 'X-Api-Version': '2026-01' },
  rateLimit: { requests: 50, perSeconds: 60 },
  errorMessagePaths: ['error.detail'],
  pagination: { type: 'cursor', param: 'after', nextPath: 'meta.next' },
  test: { request: { method: 'GET', path: '/me' }, identity: '{{response.email}}' },
  actions: [
    {
      name: 'list_tasks',
      description: 'Lists tasks of a project.',
      input: {
        type: 'object',
        properties: { project_id: { type: 'string', description: 'Project id' } },
        required: ['project_id'],
      },
      hints: { readOnly: true },
      request: { method: 'GET', path: '/projects/{project_id}/tasks' },
      response: { root: 'data', fields: ['id', 'title', 'due.date'] },
      pagination: true,
    },
  ],
});
```

Риск, отмену и привязку к общим интерфейсам манифест задаёт данными (раздел «Риск, отмена и
общие интерфейсы» ниже). Если отображение на интерфейс требует логики, которую шаблоны не выразят
(дата → `{date}` или `{dateTime}`, сборка строки фильтра, отбор результатов), встроенный манифест
получает привязку кодом вторым аргументом:

```ts
export default defineManifestConnector(manifest, {
  actions: {
    list_tasks: {
      capability: { id: 'tasks.list', mapInput: (q) => ({ filter: q.query ? `search: ${q.query}` : 'all' }) },
    },
  },
});
```

Расширение для несуществующего действия — ошибка при старте. Примеры: `google-calendar.ts`,
`todoist.ts`.

### Авторизация (`auth`)

| `type` | Что делает | Ключи по умолчанию |
| --- | --- | --- |
| `none` | Без авторизации | — |
| `api_key` | Ключ в заголовке или query (`in`, `name`, `value`) | `credentials.apiKey` |
| `bearer` | `Authorization: Bearer …` (`token`) | `credentials.token` |
| `basic` | `username` / `password` — шаблоны | задать `credentials` |
| `oauth2` | `provider` (id из реестра или описание), `scopes`; хаб проводит OAuth и обновляет токены | — |

### Шаблоны

`{{input.x}}`, `{{config.x}}`, `{{credentials.x}}`, `{{account.name}}`, в `test.identity` —
`{{response.x}}`. Строка из одного шаблона сохраняет тип значения (число остаётся числом);
отсутствующее значение убирает ключ целиком. Выполнения кода нет, только пути через точку.

### Запрос

- `path`: сегменты `{field}` берутся из входа и URL-кодируются.
- `query` и `body` — шаблоны. Если не заданы: у GET/DELETE остальные поля входа идут в query,
  у POST/PUT/PATCH — в тело. В запрос попадают только поля, объявленные во входной схеме.
- `bodyType`: `json` (по умолчанию) или `form`.

### Риск, отмена и общие интерфейсы

Как и у кодовых коннекторов, у действия манифеста есть:

- `risk`: `read`, `write` или `dangerous`. Если не задан, выводится из `hints`: `readOnly` → `read`,
  `destructive` → `dangerous`, иначе `write`. По риску хаб решает, что спрашивать у пользователя и
  что писать в журнал.
- `undo`: как отменить действие. `{ "kind": "action", "action": "delete_task" }` (другое действие
  этого же сервиса), `{ "kind": "delay", "seconds": 30 }` (хаб придерживает вызов) или
  `{ "kind": "none" }`.
- `capability`: какой общий интерфейс реализует действие (`tasks.list`, `mail.send`…, список в
  `src/connectors/capabilities.ts`). Тогда сервис попадает в единые инструменты вроде `tasks_list`.
  Если поля сервиса называются иначе, чем в интерфейсе, отображение задаётся шаблонами, без кода:

```json
"capability": {
  "id": "tasks.list",
  "input": { "text": "{{input.query}}", "max": "{{input.limit}}" },
  "output": { "id": "{{item.gid}}", "title": "{{item.name}}", "due": "{{item.due_on}}" }
}
```

`input` строит вход действия из входа интерфейса (`{{input.*}}`), `output` — элемент результата в
форме интерфейса (`{{item.*}}`, для `single`-интерфейсов это весь результат). Ошибки (неизвестный
интерфейс, риск не совпадает с интерфейсом, `undo` ссылается на несуществующее действие, шаблон
обращается не к `input`/`item`) обнаруживаются при добавлении сервиса.

### Ответ

`root` — какую часть ответа вернуть, `fields` — какие поля оставить (у объекта или каждого
элемента массива): ИИ не платит токенами за лишнее. `empty` — текст для пустого ответа (204).

### Пагинация

Действие с `pagination` (или `pagination: true` — взять общую из манифеста) получает аргумент
`cursor` и возвращает `{ items, nextCursor }`: ИИ запрашивает следующую страницу, только когда она
нужна. Варианты: `cursor` (курсор из ответа), `page` (номер страницы), `offset` (смещение/лимит),
`link` (заголовок `Link: rel="next"`), `next_url` (URL следующей страницы в ответе). Курсор
непрозрачный; URL-курсоры принимаются только на домене API, так что подделанный курсор не уведёт
ключи аккаунта на чужой сервер.

Ошибки в манифесте (параметр пути не объявлен во входе, `pagination: true` без общей пагинации,
неверное имя действия, вход `account`) обнаруживаются при регистрации коннектора, а не при вызове.

## OAuth-провайдеры

Провайдер — это сервер авторизации: адреса authorize/token/revoke, PKCE, способ аутентификации
клиента, разделитель scopes, особенности (`tokenPath` у Slack, `access_type=offline` у Google).
Реестр — `src/connectors/oauth/providers.ts`: `google`, `microsoft`, `slack`, `notion`, `github`,
`todoist`. Коннектор только ссылается на провайдера и перечисляет свои scopes:

```ts
oauth: { provider: 'google', scopes: ['https://www.googleapis.com/auth/gmail.modify'] }
```

Так одно OAuth-приложение Google обслуживает Gmail, Календарь и Диск. Новый провайдер — одна
запись в реестре.

### Хаб как OAuth-клиент

Как это работает для коннектора с `oauth`:

1. **Приложение.** Client id/secret берутся из переменных `OAUTH_APP_<ПРОВАЙДЕР>_CLIENT_ID` /
   `_CLIENT_SECRET` (одно на весь хаб) или из своего приложения пространства (`oauth_apps`, секрет
   зашифрован). Если в пространстве есть своё приложение провайдера, используется оно. Каждый
   аккаунт запоминает, каким приложением выдан токен (`appRef`), и обновляется только им.
2. **Подключение.** `/connect/<сервис>` (или `POST /api/v1/connect`) создаёт одноразовый `state`
   (привязан к пользователю, живёт 15 минут, в базе только хэш) и PKCE-пару, отправляет
   пользователя к провайдеру. Колбэк `/connect/callback` один на все провайдеры. После обмена кода
   создаётся аккаунт (или переподключается существующий, `?account=<id>`), токены шифруются
   отдельно от `credentials` (таблица `account_oauth`), проверка подключения записывает identity.
3. **Обновление.** Перед вызовом действия токен, истекающий в ближайшие 2 минуты, обновляется под
   блокировкой строки (несколько инстансов и параллельные вызовы не гоняют ротирующийся
   refresh-токен), на 401 HTTP-клиент обновляет его ещё раз. Фоновая задача обновляет токены
   заранее. `invalid_grant` помечает аккаунт `needs_reauth`.
4. **Удаление аккаунта** отзывает токен у провайдера (если у него есть `revocationUrl`).

`oauth.optional: true` (в манифесте — поле `token` в `auth`) разрешает вместо OAuth личный токен
из `credentials`: удобно для личного использования без регистрации OAuth-приложения.

## Сервисы без кода

Пространство может добавить свои сервисы, не трогая код хаба: они хранятся в таблице
`custom_connectors` и видны только этому пространству. `WorkspaceConnectorResolver` отдаёт
встроенные коннекторы и сервисы пространства вместе; встроенный id всегда главнее, поэтому свой
сервис не может выдать себя за встроенный. Скомпилированный коннектор кэшируется по версии строки.

| Запрос | Что делает |
| --- | --- |
| `GET /api/v1/services` | свои сервисы: вид, авторизация, число инструментов, последняя ошибка |
| `POST /api/v1/services` | добавить: `{"kind":"manifest","manifest":{...}}` или `{"kind":"mcp","url":"https://…/mcp","name":"Linear"}` |
| `PATCH /api/v1/services/:id` | изменить: у MCP-сервера `name`, `description`, `instructions`, `toolRisk`; у манифеста — заменить `manifest` (id не меняется) |
| `POST /api/v1/services/:id/refresh` | заново получить список инструментов внешнего MCP-сервера |
| `DELETE /api/v1/services/:id` | удалить (409, пока у сервиса есть аккаунты) |

Манифест проверяется при добавлении так же, как встроенный (ошибка — ответ 400 с причиной).

### Внешний MCP-сервер

`src/connectors/mcp-remote/connector.ts` превращает удалённый MCP-сервер (Streamable HTTP) в
обычный сервис хаба: аккаунт — это один вход на сервер, каждый удалённый инструмент — действие
`<сервис>_<инструмент>` с выбором аккаунта, а вызовы проходят через маршрутизацию, политики и
журнал хаба. Имена инструментов приводятся к snake_case (не длиннее 40 символов, повторы получают
`_2`); если у удалённого инструмента есть свой аргумент `account`, он виден ИИ как `account_arg` и
переименовывается обратно при вызове. Аргументы проверяет сам удалённый сервер.

Авторизация (`auth`): `auto` (по умолчанию), `none`, `bearer` (`credentials.token`), `header`
(`headerName` + `credentials.token`), `oauth2`. В режиме `auto` хаб:

1. пробует получить список инструментов без авторизации; получилось — сервис открытый;
2. на 401 ищет OAuth по спецификации MCP: Protected Resource Metadata (RFC 9728), затем метаданные
   сервера авторизации (RFC 8414); `resource` (RFC 8707) добавляется к запросам авторизации и токена;
3. регистрирует хаб как OAuth-клиента: Client ID Metadata Document
   (`/connect/client-metadata.json`), если хаб на https и сервер его поддерживает, иначе Dynamic
   Client Registration; полученный client id сохраняется как приложение пространства (`oauth_apps`);
4. если OAuth не найден, ждёт личный токен (`bearer`).

**Риск инструментов.** Хаб берёт его из аннотаций сервера по умолчаниям MCP: `readOnlyHint` →
`read`, `destructiveHint: false` → `write`, всё остальное (в том числе инструмент без аннотаций) →
`dangerous`. Чужой сервер — не наш код, поэтому неизвестное по умолчанию требует подтверждения.
Пространство может поменять риск отдельного инструмента:
`PATCH /api/v1/services/linear {"toolRisk":{"create_issue":"write"}}` (`null` убирает настройку).

Дальше подключение такое же, как у встроенных OAuth-сервисов: `/connect/<id>`, хаб хранит и
обновляет токены, на 401 от сервера один раз обновляет токен и повторяет вызов. Список
инструментов хранится в базе (каталог не ждёт удалённый сервер) и обновляется после подключения
первого аккаунта, по `POST /services/:id/refresh` и раз в сутки фоновой задачей
`services.refresh_tools`.

## Контрактные тесты и бюджет токенов

Каждый встроенный коннектор проверяется контрактными тестами в `test/connectors/`, без сети и
без базы. `testAccount(connector, {config, credentials, oauth, fetch})` из
`test/connectors/harness.ts` запускает действия напрямую с тем же разбором настроек, что и хаб;
`fakeRoutes({'GET /path': ответ | (req) => Response})` — фейковый сервис по таблице маршрутов
(неизвестный маршрут отвечает 404, чтобы ошибка в адресе была видна сразу), в `calls` остаются все
запросы для проверок. Ответы в таблицах написаны по документации API сервиса. Почта IMAP/SMTP
тестируется на настоящих локальных серверах (`hoodiecrow-imap`, `smtp-server`) по TLS.

Общие интерфейсы проверяет `acc.runCapability('mail.search', {...})`: он вызывает действие так
же, как хаб (каноничный вход → `mapInput` → действие → `mapOutput`), и строго сверяет результат со
схемой интерфейса, так что опечатка в имени поля роняет тест, а не пропадает молча
(`test/connectors/capabilities.test.ts`). Там же проверяется, что у каждого пишущего действия
встроенных коннекторов явно указан `risk`.

Что проверять: заголовки авторизации и обе схемы входа (OAuth и личный токен), построение запроса
(параметры, тело), компактную форму ответа, пагинацию курсором, понятные ошибки
(`ConnectorError` нужного вида) и защиту от выхода за пределы API (курсоры, пути).

`test/connectors/budget.test.ts` считает, сколько токенов стоят инструменты коннектора в контексте
модели при одном аккаунте, и держит для каждого бюджет (всего и на самый большой инструмент).
Новый коннектор без бюджета не пройдёт CI; поднимать бюджет — только вместе с изменением, которому
это нужно. Таблица размеров: `BUDGET_REPORT=1 npx vitest run test/connectors/budget.test.ts`.

## Фоновые задачи

Очередь задач на Postgres (pg-boss, схема `pgboss`): `src/jobs/queue.ts`, встроенные задачи — в
`src/jobs/builtin.ts`. Сейчас это обновление истекающих OAuth-токенов (каждые 5 минут),
ежедневная проверка подключения каждого аккаунта и ежедневное обновление списков инструментов
внешних MCP-серверов. Повторяющиеся задачи не накладываются друг на
друга и при нескольких инстансах выполняются один раз. По умолчанию задачи работают в веб-процессе;
`npm run start:worker` запускает отдельный процесс только для них (тогда на веб-сервисе
`JOBS_ENABLED=false`). Новая задача — ещё один `JobDefinition`.

## Метаданные действия

Кроме `name`, `description`, `input` и `run` у действия есть поля, по которым хаб решает, как его
показывать, проверять и исполнять.

| Поле | Зачем | По умолчанию |
| --- | --- | --- |
| `hints` | Подсказки MCP-клиентам (`readOnly`, `destructive`, `idempotent`, `openWorld`) | — |
| `risk` | `read` / `write` / `dangerous`: для политики доступа, подтверждений и журнала | `read`, если `hints.readOnly`; `dangerous`, если `hints.destructive`; иначе `write` |
| `assessRisk(input, ctx)` | Повысить риск конкретного вызова, например первое сообщение новому собеседнику → `dangerous` с причиной. Понизить нельзя; если проверка упала, вызов считается `dangerous` | — |
| `undo` | Как отменить: `{ kind: 'action', action: 'delete_message' }`, `{ kind: 'delay', seconds: 10 }` (окно отмены) или `{ kind: 'none' }` | не указано |
| `capability` | Какую общую операцию реализует действие (`'mail.search'`, можно массив и `{ id, mapInput, mapOutput }`) | — |
| `response.fields` | Поля результата, которые ИИ может выбрать аргументом `fields` (хаб добавит его сам) | аргумента нет |
| `response.maxTokens` | Свой бюджет размера ответа | `TOOL_RESULT_MAX_TOKENS` (2000) |
| `rateLimit` | Лимит на аккаунт для действия `{ requests, perSeconds }`; у коннектора — общий лимит на аккаунт | — |
| `requiresConfirmation` | Пользователь подтверждает каждый вызов, и правила доступа это не отключают. Для действий, которые удаляют данные без возврата или открывают новый путь для данных (так помечены, например, `anyconnect_remove_account` и `anyconnect_add_service`) | `false` |

Правила, которые проверяет реестр при старте:

- имена входов `account` и `fields` зарезервированы хабом;
- id коннектора не может совпадать с именем общего интерфейса (`mail`, `messages`, `calendar`,
  `files`, `tasks`, `contacts`) и со служебными (`anyconnect`, `hub`, `mcp`);
- `undo.action` должен существовать в том же коннекторе;
- читающее действие может реализовать только читающую возможность, пишущее — только пишущую;
- одну возможность в коннекторе реализует одно действие.

Указывайте `risk` явно у всех пишущих действий. Без него запись считается `write`, но в MCP
уходит `destructiveHint: true` (осторожное значение по спецификации), и клиенты будут чаще
спрашивать пользователя.

## Тексты для сайта и форма подключения (`ui`)

Описания действий и полей в схемах пишутся для ИИ и остаются английскими. Для людей коннектор может
задать необязательное поле `ui`: тексты на языках сайта и раскладку формы `/connect/<сервис>`.
Сайт берёт их на страницах подключения и `/services/<сервис>`; каталог MCP их не видит.

```ts
defineConnector({
  // ...
  ui: {
    // Сразу видны эти поля и все обязательные; остальные — под «Дополнительно».
    primaryFields: ['email', 'password', 'provider'],
    locales: {
      ru: {
        name: 'Почта (IMAP/SMTP)', // необязательно
        description: 'Любой почтовый ящик по IMAP/SMTP…', // необязательно
        fields: {
          password: { label: 'Пароль приложения', hint: 'Создаётся в настройках безопасности почты' },
          provider: {
            label: 'Почтовый сервис',
            placeholder: 'Определить по адресу', // у списка — подпись пустого варианта
            options: { yandex: 'Яндекс Почта', custom: 'Другой сервер' },
          },
        },
        actions: { search: { title: 'Поиск писем', description: 'Ищет письма в папке, сначала новые.' } },
      },
      en: { /* те же ключи */ },
    },
  },
});
```

- Ключи `fields` — ключи `config` и `credentials` (у них общее пространство имён), ключи
  `actions` — `name` действий. В `defineConnector` ключи полей и `primaryFields` проверяет
  TypeScript; коннектору-манифесту тексты добавляет `withUi(defineManifestConnector({...}), ui)`.
- Порядок поиска текста: язык страницы → английский → `title`/`description` схемы или действия →
  ключ поля («imapHost» → «Imap Host»). Запись поля в языке заменяет его тексты целиком: если у
  русской записи нет `hint`, подсказки нет (английская не подставится).
- Подписи вариантов списка ищутся по каждому значению отдельно; значение без подписи показывается
  как есть.
- Без `primaryFields` все поля видны сразу. Блок «Дополнительно» раскрывается сам, если в нём есть
  введённое значение или поле с ошибкой. Ошибки проверки называют поле его подписью.
- У встроенных коннекторов тексты есть на русском и английском для всех полей, вариантов и действий;
  это проверяет `test/connectors/ui-texts.test.ts`. Стиль русских текстов: коротко и просто, как в
  хорошем русском сервисе («Пароль приложения», «Адрес сервера IMAP»), «вы» со строчной, буква «ё»,
  без англицизмов там, где есть обычное слово.

## Общие интерфейсы (capabilities)

Описаны в `src/connectors/capabilities.ts`: вход и выход каждой операции заданы zod-схемами.

| Интерфейс | Операции |
| --- | --- |
| `messages` | `search`, `list_chats`, `read_chat`, `send` |
| `mail` | `search`, `read`, `send` |
| `calendar` | `list_events`, `create_event` |
| `files` | `search`, `read` |
| `tasks` | `list`, `create` |
| `contacts` | `search` |

Действие получает каноничный вход (или результат `mapInput`), а возвращает каноничный выход:
для списочных операций — массив элементов или `{ items, nextCursor }`, для одиночных — объект
(или результат `mapOutput`). Поля, которых нет в схеме, в едином виде отбрасываются, поэтому
родной результат действия может быть богаче. Хаб собирает из этого единые инструменты
(`messages_search` по всем мессенджерам и ящикам сразу), как только операцию реализуют хотя бы
два разных коннектора (см. [ARCHITECTURE.md](ARCHITECTURE.md#как-аккаунты-превращаются-в-инструменты)).

Новая операция добавляется в `CAPABILITIES` и сразу доступна всем коннекторам; менять ядро не
нужно.

## Компактные ответы

Каждый токен ответа отнимает контекст у задачи. В SDK есть помощники:

- `htmlToText(html, { maxLength })` — письма и rich text в читаемый текст, ссылки как
  `текст (url)`;
- `truncateText(text, max)` — обрезка по слову с пометкой «ещё N символов»;
- `pickFields(value, fields)` — только нужные поля (пути через точку, `id` сохраняется всегда);
- `page(items, { nextCursor, total })`, `encodeCursor` / `decodeCursor` — постраничная выдача с
  непрозрачным курсором;
- `compact(value)` — без пустых значений.

Хаб дополнительно применяет к каждому ответу бюджет размера: убирает пустые поля, сокращает
длинные строки, оставляет столько элементов списка, сколько помещается, и добавляет пометку
`truncated` с подсказкой, как сузить запрос. JSON отдаётся без отступов.

## Ошибки

Бросайте `ConnectorError(kind, message, { retryAfterSeconds })`. `auth` помечает аккаунт как
требующий переподключения. `rate_limited` и `upstream` у идемпотентных действий хаб сам
повторяет с паузой (до 5 секунд), у неидемпотентных — никогда, чтобы не сделать запись дважды.
