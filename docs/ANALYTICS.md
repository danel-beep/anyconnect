# Аналитика

Собственная аналитика сайта и продукта в админ-панели (`/admin/analytics`): откуда приходят
посетители, на каком языке и из каких стран, кто из них регистрируется, подключает ИИ-приложение
и сервисы, пользуется и платит; чем пользуются больше всего, какие тарифы активны, как
удерживаются пользователи. Сторонних счётчиков (Google Analytics, Метрика) нет, cookie для
аналитики не ставятся.

Код: `src/analytics/` (сбор, хранение, отчёты), `src/routes/analytics.ts` (middleware страниц),
`src/web/admin-analytics.tsx` (страница админки), тексты в `src/web/i18n/analytics.ts`.

## Как устроен сбор

```
запрос страницы → pageAnalytics() (после ответа) → Analytics.pageView() → буфер в памяти
                                                                          ↓ каждые 5 с
                                analytics_visits / analytics_pages / analytics_events (upsert)
```

- **Ничего не ждёт базу.** Middleware срабатывает после того, как страница отрисована, и только
  кладёт простые значения в массив. Раз в `ANALYTICS_FLUSH_SECONDS` (5 с) или при 2000 записях
  буфер сворачивается в дневные агрегаты и пишется несколькими пакетными `INSERT … ON CONFLICT`.
  Ошибка записи уходит в трекер ошибок, пакет отбрасывается: аналитика не повторяет запись в
  упавшую базу и не тормозит сайт. Если буфер переполнен (20 000 просмотров), лишние не
  пишутся и считаются событием `analytics.dropped`.
- **Считаются** ответы HTML 200 на GET (не prefetch). Не считаются админка, API, MCP, вебхуки,
  статика, 404 и редиректы.
- **Роботы** (поисковые, ИИ-краулеры GPTBot/ClaudeBot/PerplexityBot, превью ссылок, мониторинг,
  скрипты) в визиты не попадают: они считаются событием `crawler` по семейству, в том числе для
  `robots.txt`, `llms.txt`, карт сайта и лент. Это полезно для GEO: видно, читают ли сайт ИИ.
- **Страницы кабинета** (`/app`, `/connect`, `/security`…) считаются только как просмотры страниц
  (что используют в кабинете), а не как визиты трафика.

## Посетитель без cookie

Посетитель — это `SHA-256(соль дня, IP (IPv6 по /64), User-Agent)`, обрезанный до 22 символов.
Соль случайная, своя на каждый день UTC, хранится в `analytics_salts` (общая для всех инстансов)
и удаляется через два дня задачей `analytics.prune`. После этого визит невозможно связать ни с
адресом, ни с человеком, даже нам. IP-адрес и строка браузера не сохраняются, страна определяется
на лету.

Следствия: один человек в разные дни — разные визиты («визит» = посетитель-день); вошедшие
пользователи (есть cookie сессии) помечаются `known` и не входят в цифры трафика, их визиты
показаны отдельно.

## Источник трафика

Порядок определения (`touchFrom` в `src/analytics/classify.ts`):

1. UTM-метки: `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`.
2. Идентификаторы рекламных кликов без меток (`gclid`, `fbclid`, `msclkid`, `yclid`…) → канал `paid`.
3. Ссылка-приглашение от пользователя (`?ref=<код>`, программа приглашений) → источник
   `user_invite`, канал `invite`. Сам код в аналитику не попадает.
4. Сайт-источник (`Referer`): ИИ-ассистенты (`ai`: ChatGPT, Claude, Perplexity, Gemini…),
   поисковики (`organic`), соцсети и сообщества (`social`), почта, остальные сайты (`referral`).
5. Ссылка-приглашение в команду (`/invite/…`) → `team_invite`.
6. Иначе `direct`.

Источник визита — первый непрямой за день: если человек сначала зашёл напрямую, а потом по
рекламе, визит получает рекламный источник. Метки приводятся к виду `[a-z0-9._-]`, до 64 символов
(кампания до 100).

### Метки Telegram Ads

Реклама в Telegram ведёт только в канал или бота, поэтому цепочка такая: объявление → бот
`/start <метка>` → кнопка на сайт с той же меткой:

```
https://manyplug.com/?utm_source=telegram&utm_medium=ads&utm_campaign=tg_ai_1
```

Метка — полезная нагрузка `/start` (`[a-z0-9_-]`, до 64 символов), например `tg_<тема>_<номер>`.
Бот (`TelegramLanding`, `src/growth/telegram-landing.ts`) отвечает на `/start <метка>` кнопкой на
сайт с этой меткой и считает запуск событием `bot.start` с меткой в `key` (без метки — `none`;
подключено через `onStart` в `src/services.ts`). Во вкладке «Воронка» с разбивкой по кампании
появляется колонка «Запуски бота»: в одной строке видны запуски, визиты, регистрации и оплаты
каждой кампании. Колонка показывается, только если нет других фильтров, кроме кампании: у
запуска бота нет страны, устройства и прочих измерений.

## Страна, язык, устройство

- **Страна**: сначала заголовок CDN (`ANALYTICS_COUNTRY_HEADERS`, по умолчанию `cf-ipcountry`,
  `x-vercel-ip-country`, `cloudfront-viewer-country`), иначе локальная база IP → страна
  (`@ip-location-db/geo-whois-asn-country-mmdb`, общественное достояние CC0, ~8 МБ, загружается
  при первом поиске, поиск — микросекунды, без внешних запросов). Свою базу в формате MaxMind
  можно указать в `ANALYTICS_GEOIP_DB`, `off` выключает определение по IP. Сама база обновляется
  вместе с версией пакета (`npm update @ip-location-db/geo-whois-asn-country-mmdb`).
- **Язык**: основной язык из `Accept-Language` (`en`, `de`, `ru`), а не язык интерфейса сайта.
- **Устройство, браузер, ОС**: семейства из `User-Agent` (компьютер / телефон / планшет; Chrome,
  Safari, Telegram, встроенный браузер приложения…), без версий.

## Регистрации и воронка

При регистрации через Google (`/auth/:provider/callback`, `created = true`) хаб считает хэш того
же браузера с солью сегодняшнего и вчерашнего дня и ищет визит (сначала с непрямым источником).
Найденный источник, кампания, страница входа, страна, язык и устройство записываются один раз в
`user_attribution` (`matched = true`). Если визита нет (заходил раньше чем вчера, другой IP,
регистрация до появления аналитики) — `source = unknown`, `matched = false`, а страна, язык и
устройство берутся из запроса регистрации.

Воронка (вкладка «Воронка») для регистраций выбранного периода, с разбивкой по источнику,
кампании, каналу, стране, языку, устройству, странице входа или сайту-источнику:

| Шаг | Как считается |
| --- | --- |
| Запуски бота | `bot.start` с той же меткой (только при разбивке по кампании) |
| Визиты | `analytics_visits` той же группы за период, без вошедших |
| Зарегистрировались | `users.created_at` в периоде (+ `user_attribution`) |
| Подключили ИИ-приложение | есть `oauth_grants` или `api_tokens` пользователя |
| Подключили сервис | есть `accounts` в пространстве, которым он владеет |
| Сделали вызов | есть `usage_counters.calls > 0` в его пространстве |
| Платят | подписка платёжного провайдера (не `manual`, не `referral`, есть `external_id`, не `free`) в статусе active / trialing / past_due, так же как на странице «Выручка» (`src/admin/revenue.ts`) |
| MRR | цена тарифа × купленное количество (сейчас всегда 1; годовая цена / 12) по `src/billing/plans.ts`, только по личным пространствам: у команды своего тарифа нет |

## Остальные вкладки

- **Трафик**: визиты, просмотры, доля ушедших после одной страницы, регистрации и конверсия;
  графики по дням; разбивки по 10 измерениям (клик по строке добавляет фильтр
  `?f.<измерение>=<значение>`, фильтры действуют на все цифры страницы); популярные страницы;
  роботы.
- **Продукт**: вызовы по сервисам и инструментам (`usage_counters`), активные пользователи
  по дням, WAU / MAU и их отношение, подключённые ИИ-приложения, аккаунты по сервисам вместе с
  «начали подключать» (событие `connect.start`) и долей дошедших до конца, страницы кабинета, все
  события продукта.
- **Тарифы**: какие тарифы действуют и как ими пользуются. Для каждого тарифа и способа
  (платный, пробный период, бесплатный, подарен админом или за приглашения): пространства, места,
  сколько из них делали вызовы за период и сколько вызовов, MRR. Плюс MRR по источникам трафика.
  Действующий тариф определяется как в `Entitlements.planFor`: отменённая, приостановленная или
  истёкшая подписка — это бесплатный тариф. Деньги подробно (конверсия пробного периода, отток,
  приглашения) — на отдельной странице «Выручка» (`/admin/revenue`), вкладка ссылается на неё и не
  дублирует её.
- **Удержание**: недельные когорты регистраций за 12 недель и доля сделавших хотя бы один вызов
  на неделе N.

Отчёты (`AnalyticsReports` в `src/analytics/reports.ts`) — несколько сгруппированных запросов
(`GROUPING SETS` — все разбивки одним запросом) по дневным агрегатам; результат кэшируется на
минуту в памяти, поэтому повторное открытие админки ничего не стоит.

## Как расширять

- **Новое событие продукта**: `services.analytics.track('name', key)` в месте, где оно
  происходит (имя `[a-z][a-z0-9._-]{0,39}`, ключ — сервис, тариф, кампания). Оно сразу появится в
  списке событий на вкладке «Продукт»; подпись — ключ `an.event.<name>` в `i18n/analytics.ts`.
  Сейчас считаются `signup` (провайдер), `connect.start` (сервис), `checkout.start`
  (`<тариф>_<период>`), `bot.start` (метка кампании), `crawler` (семейство), `analytics.dropped`.
- **Новое измерение визита**: колонка в `analytics_visits` и `user_attribution` (миграция), имя в
  `DIMENSIONS`/`COLUMN` (`reports.ts`) и значение в `newVisit` (`collector.ts`).
- **Новый отчёт**: метод в `AnalyticsReports` (через `cached`) и вкладка в `ANALYTICS_TABS`.
- **Другой способ определения страны**: реализация `GeoResolver` (`geo.ts`).
- **Объём**: строк визитов — по одной на посетителя в день, при 1000 посетителей в день это
  ~400 тыс. строк за `ANALYTICS_RETENTION_DAYS` (400 дней), запросы идут по первичному ключу
  `(day, visitor)`. Если трафик вырастет на порядки, следующий шаг — ночные свёртки по дням и
  измерениям за закрытые дни за тем же интерфейсом `AnalyticsReports`.

## Хранение

| Таблица | Что | Сколько |
| --- | --- | --- |
| `analytics_salts` | соль дня | 2 дня |
| `analytics_visits` | посетитель-день: источник, страница входа, страна, язык, устройство, просмотры | `ANALYTICS_RETENTION_DAYS` |
| `analytics_pages` | просмотры по странице и дню | `ANALYTICS_RETENTION_DAYS` |
| `analytics_events` | счётчики событий по дню | `ANALYTICS_RETENTION_DAYS` |
| `user_attribution` | откуда пришёл пользователь | пока существует пользователь |

## Переменные

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `ANALYTICS` | `on` | Выключает сбор целиком (`off`). Отчёты по продукту и выручке работают и без него. |
| `ANALYTICS_RETENTION_DAYS` | `400` | Сколько дней хранить визиты и счётчики. |
| `ANALYTICS_COUNTRY_HEADERS` | `cf-ipcountry,x-vercel-ip-country,cloudfront-viewer-country` | Заголовки CDN со страной посетителя. |
| `ANALYTICS_GEOIP_DB` | встроенная база | Путь к своей базе IP → страна (MaxMind), или `off`. |
| `ANALYTICS_FLUSH_SECONDS` | `5` | Как часто писать буфер в базу. |
