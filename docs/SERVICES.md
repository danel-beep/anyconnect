# Встроенные сервисы

Сорок пять коннекторов идут в коробке. У каждого может быть сколько угодно аккаунтов: две почты
Gmail, рабочий и личный Outlook, пять ящиков на Яндексе. ИИ видит один набор инструментов на сервис
и выбирает аккаунт аргументом `account` (или, по настройке пространства, видит отдельные инструменты
на каждый аккаунт).

Как добавить аккаунт: через OAuth — `https://<хаб>/connect/<id>?label=Рабочая` (подробно в
README, раздел «Подключение через OAuth»), с ключом — `POST /api/v1/accounts` или CLI:

```bash
npm run cli -- accounts:add --connector imap --label "Яндекс" \
  --config '{"email":"me@yandex.ru"}' --credentials '{"password":"пароль приложения"}'
```

Схемы настроек (`config`) и ключей (`credentials`) каждого сервиса отдаёт `GET /api/v1/connectors`.

## Почта IMAP/SMTP

Подходит для любого почтового сервера. Для Gmail, Yahoo Mail, Яндекса, Mail.ru, iCloud, Outlook.com и
Fastmail серверы подставляются сами по адресу почты (`provider` можно указать явно), для остальных
`provider: "custom"` и `imapHost` / `smtpHost` (порты и шифрование по умолчанию 993/TLS и 465/TLS).

- Нужен **пароль приложения**, а не основной пароль: Яндекс — «Управление аккаунтом → Безопасность →
  Пароли приложений» (и включить IMAP в настройках почты); Mail.ru — «Безопасность → Пароли для
  внешних приложений»; Gmail — пароль приложения при включённой двухэтапной проверке; iCloud —
  appleid.apple.com → «Пароли приложений»; Yahoo — Account security → Generate app password.
- Zoho и GMX подключаются как «Другой сервер» (у Zoho серверы зависят от региона аккаунта:
  `imap.zoho.com` или `imap.zoho.eu`). Proton Mail даёт IMAP только через Proton Mail Bridge на
  компьютере пользователя, поэтому из облака не подключается; форма об этом предупреждает.
- Отправленные письма сохраняются в «Отправленные» (`saveSentCopy`), кроме Gmail, Outlook.com и
  Yahoo, которые делают это сами. Для Yahoo это стоит проверить на живом ящике: если копий окажется
  две или ни одной, поправьте `savesSentCopy` в `presets.ts` (у аккаунта есть и ручная настройка).
- Идентификатор письма — `папка:uid`; он меняется при переносе в другую папку.
- Соединение IMAP держится минуту после последнего вызова и переиспользуется.
- `allowInvalidCertificate` — только для своего сервера с самоподписанным сертификатом.
- Серверы во внутренней сети недоступны, пока хаб не запущен с `ALLOW_PRIVATE_NETWORK=true`.

## Google: Gmail, Calendar, Drive

Одно OAuth-приложение Google на все три сервиса (каждый спрашивает только свои права).

1. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials) создайте проект и
   включите Gmail API, Google Calendar API и Google Drive API.
2. «OAuth consent screen»: тип External; пока приложение в статусе Testing, добавьте свои адреса в
   Test users. В Testing refresh-токен живёт 7 дней; для постоянной работы переведите приложение в
   Production (для личного использования проверка Google не обязательна, будет предупреждение на
   экране согласия).
3. «Credentials → Create credentials → OAuth client ID», тип Web application, Authorized redirect
   URI `https://<хаб>/connect/callback`.
4. `OAUTH_APP_GOOGLE_CLIENT_ID` и `OAUTH_APP_GOOGLE_CLIENT_SECRET` в переменные окружения хаба.

Права: Gmail — `gmail.modify` (чтение, отправка, ярлыки; без безвозвратного удаления), Calendar —
`calendar`, Drive — `drive`.

- **Gmail**: поиск принимает синтаксис Gmail (`from:bank is:unread newer_than:7d`). Ответ уходит в
  ту же цепочку, пересылка прикладывает оригинал со всеми вложениями.
- **Calendar**: времена в RFC 3339 со смещением (`2026-11-05T15:00:00+03:00`), повторяющиеся
  события разворачиваются в отдельные. Приглашения рассылаются, только если `sendUpdates: "all"`.
- **Drive**: Google Docs и Slides читаются как текст, Sheets — как CSV (первый лист), обычные
  текстовые файлы до 5 МБ — как есть. Удаление — перенос в корзину (восстанавливается 30 дней).

## Microsoft: Outlook

1. В [Microsoft Entra](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade)
   «New registration»: Supported account types — «Accounts in any organizational directory and
   personal Microsoft accounts», Redirect URI (Web) `https://<хаб>/connect/callback`.
2. «Certificates & secrets → New client secret».
3. `OAUTH_APP_MICROSOFT_CLIENT_ID` и `OAUTH_APP_MICROSOFT_CLIENT_SECRET` в окружение хаба.

Права: `Mail.ReadWrite`, `Mail.Send`, `Calendars.ReadWrite`, `MailboxSettings.Read`. В рабочих
аккаунтах организация может требовать согласия администратора.

- Поиск принимает синтаксис Outlook (`from:ann subject:invoice hasattachments:true`). Папки:
  `inbox`, `sent`, `drafts`, `trash`, `junk`, `archive`, `all` или id из `outlook_list_folders`.
- Ответ и пересылка идут штатными средствами Outlook, поэтому письма остаются в одной беседе.
- После переноса письмо получает новый id (действие его возвращает).
- Часовой пояс календаря задаётся в настройках аккаунта (`timeZone`, по умолчанию UTC). Время
  события можно передать со смещением, без смещения (тогда в поясе аккаунта) или датой для
  события на весь день.

## Slack

Через OAuth: приложение на [api.slack.com/apps](https://api.slack.com/apps), в «OAuth &
Permissions» redirect URL `https://<хаб>/connect/callback`, затем `OAUTH_APP_SLACK_CLIENT_ID` /
`_SECRET`. Хаб просит пользовательские права (поиск работает только с пользовательским токеном).

Без OAuth: токен пользователя `xoxp-…` или бота `xoxb-…` в `credentials.token`. Бот не умеет
искать сообщения и видит только каналы, куда его добавили.

Канал можно указать id, `#название` или `@пользователь` (личные сообщения).

## Notion

Проще всего — внутренняя интеграция: [notion.so/profile/integrations](https://www.notion.so/profile/integrations)
→ «New integration», токен в `credentials.token`, затем на нужных страницах «⋯ → Connections →
добавить интеграцию». Интеграция видит только страницы, к которым её подключили.

Через OAuth: публичная интеграция с redirect URI `https://<хаб>/connect/callback` и
`OAUTH_APP_NOTION_CLIENT_ID` / `_SECRET`; страницы выбираются на экране согласия.

Страницы читаются в Markdown, принимаются id и ссылки notion.so. Свойства базы задаются простыми
значениями: `{"Status": "Готово", "Срок": "2026-11-05", "Теги": ["работа"]}`.

## GitHub

Без OAuth: [личный токен](https://github.com/settings/personal-access-tokens) (fine-grained:
доступ к нужным репозиториям, права Issues и Pull requests на чтение и запись, Metadata на чтение;
для уведомлений нужен classic-токен с `notifications`).

Через OAuth: OAuth App на [github.com/settings/developers](https://github.com/settings/developers)
с callback `https://<хаб>/connect/callback` и `OAUTH_APP_GITHUB_CLIENT_ID` / `_SECRET`. Права:
`repo`, `notifications`, `read:user`.

## Todoist

Без OAuth: API-токен из «Настройки → Интеграции → Для разработчиков». Через OAuth: приложение в
[консоли Todoist](https://developer.todoist.com/appconsole.html) с redirect URI
`https://<хаб>/connect/callback`, права `data:read_write,data:delete`.

Поиск задач принимает фильтры Todoist: `today`, `overdue`, `7 days`, `#Работа & p1`, `search: текст`.

## Jira

Jira Cloud по REST API v2 (описания и комментарии простым текстом). В форме: имя сайта (`acme` для
`acme.atlassian.net`), почта Atlassian и API-токен с
[id.atlassian.com](https://id.atlassian.com/manage-profile/security/api-tokens) — обычный
«Create API token», не «with scopes» (токены со scopes работают только через шлюз
`api.atlassian.com`). Поиск по JQL идёт через `/search/jql`: запрос без условий (одна сортировка)
Jira отклоняет. Статус меняется в два шага: `jira_list_transitions` → `jira_transition_issue`.
В `tasks_list` попадают задачи, назначенные на вас; `tasks_create` требует ключ проекта в `project`.

## Linear

GraphQL API, личный ключ из Settings → Security & access → Personal API keys (заголовок
`Authorization` без `Bearer`). Задачи адресуются идентификатором (`ENG-42`), команда — ключом,
статус — названием (хаб сам находит id). Если команда одна, её можно не указывать. Приоритеты
Linear (1 срочный … 4 низкий) в едином виде переводятся в общую шкалу (4 срочно … 1 обычный).
Удаление переносит задачу в корзину Linear на 30 дней.

## Asana

Личный токен из [консоли разработчика](https://app.asana.com/0/my-apps). Если у аккаунта одно
рабочее пространство, оно подставляется само, при нескольких ИИ передаёт `workspace`. Проект можно
назвать словами: хаб найдёт его id через typeahead. Без проекта `find_tasks` показывает ваши
задачи, с `query` ищет по названию (поиск Asana по всем полям есть только на платных тарифах).

## Trello

Trello выдаёт API-ключи только Power-Up’ам: создайте Power-Up в
[админке](https://trello.com/power-ups/admin), сгенерируйте API-ключ и рядом по ссылке Token —
токен. Ключ и токен уходят в заголовке `Authorization: OAuth oauth_consumer_key=…, oauth_token=…`,
а не в адресе, поэтому не попадают в логи прокси. `tasks_list` отдаёт ваши открытые карточки
(`@me is:open`); создание через `tasks_create` не поддержано — Trello нужен id списка.

## Airtable

Личный токен с [airtable.com/create/tokens](https://airtable.com/create/tokens), права
`data.records:read`, `data.records:write`, `schema.bases:read` и доступ к нужным базам. ИИ сначала
смотрит структуру базы (`airtable_get_base_schema`), потом читает записи с формулой
`filterByFormula`. Записи создаются и меняются пачками до 10 с `typecast` (новые варианты списков
создаются сами). Лимит Airtable — 5 запросов в секунду на базу, хаб держит его на аккаунт.

## HubSpot

Токен частного приложения: «Настройки → Интеграции → Частные приложения» (в новых аккаунтах —
«Разработка → Устаревшие приложения → Создать → Частное»), права
`crm.objects.contacts/companies/deals.read` и `.write`. Поиск — полнотекстовый по основным
свойствам; этапы сделок — это id, их отдаёт `hubspot_list_pipelines`. HubSpot реализует единый
`contacts_search`.

## Confluence

Тот же токен Atlassian, что и для Jira (см. выше). Чтение — через `body-format=view`, HTML
превращается в текст. Новые страницы и комментарии принимают простой текст (абзацы через пустую
строку, хаб оборачивает их в `<p>`) или готовый storage XHTML. Изменение страницы само берёт
текущую версию и записывает следующую. Confluence реализует единые `files_search` / `files_read`.

## GitLab

Токен `glpat-…` с правом `api` (или `read_api`, чтобы только читать). Для своего сервера в форме
указывается хост (`gitlab.acme.com`); внутренние адреса недоступны без `ALLOW_PRIVATE_NETWORK`.
Проект — id или полный путь (`group/project`), задача и MR — номер `iid` в проекте.

## ClickUp

Личный токен `pk_…` (заголовок `Authorization` без `Bearer`). Рабочее пространство подставляется
само, если оно одно; список можно назвать словами — хаб найдёт его во всех пространствах и папках.
`find_tasks` без списка — ваши задачи; поиск по словам идёт по названиям в пределах страницы
(у ClickUp нет текстового поиска в API). Приоритеты ClickUp (1 срочный … 4 низкий) переводятся в
общую шкалу. В `tasks_create` поле `project` — имя списка.

## Calendly

Личный токен из Integrations → API & Webhooks. Все запросы ограничены вашим пользователем.
Встречи — в едином `calendar_list_events`. Отмена — `dangerous` (участники получают письмо).

## Zendesk

Авторизация `почта/token:токен`. Поиск всегда добавляет `type:ticket`. Ответ клиенту (`reply`) —
`dangerous`, внутренняя заметка — `write`. Пагинация — по `next_page` в пределах сайта.

## Intercom

Токен приложения из Developer Hub; регион (`us`/`eu`/`au`) выбирает адрес API. Версия API
закреплена заголовком `Intercom-Version: 2.11`. Ответы и заметки уходят от имени владельца токена
(`admin_id` хаб берёт из `/me`); закрытие с сообщением клиенту поднимает риск до `dangerous`.

## Pipedrive

Личный токен из Personal preferences → API, в заголовке `x-api-token` (не в адресе). Поиск — от
двух символов, пагинация по `next_start`. Этапы сделок — id из `pipedrive_list_stages`.

## Google Sheets

То же OAuth-приложение Google, права `spreadsheets` и `drive.metadata.readonly` (чтобы искать
таблицы по названию). Их нужно добавить на экран согласия в Google Cloud Console. Таблицу можно
передать id или ссылкой. Значения пишутся как при вводе руками (`USER_ENTERED`): формулы и даты
работают.

## monday.com

Личный токен (аватар → Developers → My access tokens) без префикса `Bearer`, версия API закреплена
заголовком `API-Version: 2025-04`. GraphQL отдаёт ошибки в ответе 200, коннектор переводит их в
ошибки хаба (`ComplexityException` — `rate_limited`). Значения колонок задаются по id колонки:
`monday_get_board` показывает id, типы и варианты статусов. Удаления нет, только архив (30 дней).

## Freshdesk

Ключ агента как имя пользователя basic-авторизации (пароль `X`). Статусы и приоритеты — числа
(2 открыт, 3 ждёт, 4 решён, 5 закрыт). Поиск — синтаксис фильтров Freshdesk, хаб сам берёт его в
кавычки; не больше 10 страниц по 30. Ответ клиенту — `dangerous`, заметки по умолчанию приватные.

## Sentry

Личный токен (Settings → Account → Personal Tokens) и slug организации; адрес — `sentry.io`,
`de.sentry.io` для данных в ЕС или свой сервер. Пагинация по заголовку `Link`: Sentry всегда
присылает ссылку `next` и помечает последнюю страницу `results="false"`, движок манифестов это
учитывает.

## Figma

Личный токен в заголовке `X-Figma-Token`. Файл задаётся ключом из ссылки. `figma_get_file` читает
только два уровня дерева (страницы и фреймы), детали — `figma_get_nodes`. Комментарий на фрейме —
отдельное действие `comment_on_node`, потому что Figma требует для него и узел, и смещение.

## WordPress

Пароль приложения (WordPress 5.6+, HTTPS), basic-авторизация именем пользователя. Адрес сайта
может включать путь (`acme.com/blog`). Новые записи — только черновики; публикация и отложенная
публикация — отдельное действие `publish_post` с риском `dangerous`. Пагинация по `Link`.

## Mailchimp

Ключ API и его дата-центр (окончание ключа после дефиса) — дата-центр выбирает адрес API.
Подписчики адресуются почтой внутри аудитории; новые по умолчанию `pending` (письмо с
подтверждением). Теги ставятся и снимаются списком `{ name, status: active|inactive }`.

## Typeform

Личный токен; для аккаунтов с данными в ЕС — сервер `api.eu.typeform.com`. Ответы только
завершённые, новые первыми; следующая страница — `before` с токеном последнего ответа. Удаление
ответов — `dangerous`.

## Vercel

Токен из Account Settings → Tokens; для команды — её `team_…` в настройках аккаунта, он
добавляется ко всем запросам (`teamId`). Пагинация — курсор `until` из `pagination.next`. Перевод
деплоя в продакшен (он же откат) — `dangerous`.

## Cloudflare

API-токен с шаблоном Edit zone DNS (и Cache Purge, если нужно); Global API Key не поддерживается
намеренно. Изменение и удаление DNS-записей и сброс всего кэша — `dangerous`, добавление записи и
сброс кэша отдельных адресов — `write`.

## Bitbucket

Пароли приложений Bitbucket больше не выдаются, поэтому — API-токен Atlassian с правами Bitbucket и
почта аккаунта (basic). Workspace задаётся в настройках и входит в базовый адрес. Построчный
комментарий — отдельное действие, мерж — `dangerous`.

## Brevo

Ключ в заголовке `api-key`. `save_contact` создаёт или обновляет контакт (`updateEnabled`).
Транзакционное письмо — `dangerous` и уходит только с подтверждённого в Brevo отправителя. Если в
Brevo включён список разрешённых IP, облачные запросы будут отклонены.

## Cal.com

API v2, ключ `cal_…` как Bearer. Версия API задаётся заголовком `cal-api-version` в каждом
действии. Записи входят в единый `calendar_list_events`. Отмена — `dangerous` (участники получают
письмо).

## Webflow

Токен сайта (Site settings → Apps & integrations → API access) — один аккаунт на сайт. Записи CMS
создаются черновиками, публикация — отдельное действие `dangerous`. Поля записей задаются по slug
поля из `webflow_get_collection`.

## Zoom

Пользователь создаёт своё приложение Server-to-Server OAuth в Zoom Marketplace (оно не публикуется)
и вставляет Account ID, Client ID и Client Secret. Коннектор меняет их на часовой токен
(`grant_type=account_credentials`) и держит его в памяти процесса по id аккаунта; при смене
секрета токен берётся заново. Неверные данные приложения — ошибка `auth`. Встречи входят в единые
`calendar_list_events` и `calendar_create_event`; отмена — `dangerous`.

## Miro

Токен своего приложения Miro (Install app and get OAuth token) с правами `boards:read` и
`boards:write`; истечение токенов в приложении нужно выключить. Id доски с `=` в пути кодируется.

## SendGrid

Ключ `SG.…` как Bearer; сервер `api.eu.sendgrid.com` для субаккаунтов в ЕС. Письма и письма по
шаблону — `dangerous`, уходят только с подтверждённого отправителя. Изменения контактов SendGrid
применяет асинхронно (ответ — `job_id`).

## Smartsheet

Личный токен; регион (`api.smartsheet.com`, `.eu`, `.au`) выбирает адрес API. Ячейки задаются по id
столбца из `smartsheet_get_sheet`; строки отправляются массивом как есть.

## Stripe

Ключ `sk_live_…`/`sk_test_…` или, лучше, ограниченный `rk_…` с правами только на нужное
(Customers, Charges/PaymentIntents, Invoices, Subscriptions — чтение; Refunds — запись, если
нужны возвраты). Отдельный аккаунт на каждый режим или каждую компанию.

## Любой HTTP API

Для сервиса, у которого нет своего коннектора, но есть REST API. В настройках — `baseUrl`
(например `https://api.example.com/v2`), способ авторизации (`none`, `bearer`, `header`, `query`,
`basic`) и постоянные заголовки. ИИ передаёт путь относительно базового адреса: выйти за его
пределы, обратиться к другому хосту или во внутреннюю сеть нельзя. Большие ответы обрезаются по
целым элементам, можно попросить только нужные поля (`select`) или вложенный массив (`root`).

Для постоянного использования сервиса лучше описать его HTTP-манифестом (см.
[CONNECTORS.md](CONNECTORS.md), «Сервисы без кода»): у ИИ будут понятные отдельные инструменты.

## Единые инструменты

Коннекторы реализуют общие интерфейсы хаба, поэтому, когда подключено два сервиса одного рода, ИИ
получает один инструмент на все сразу: например, `mail_search` ищет и в Gmail, и в Outlook, и в
Яндексе.

| Интерфейс | Сервисы |
| --- | --- |
| почта (`mail_search`, `mail_read`, `mail_send`) | IMAP/SMTP, Gmail, Outlook |
| календарь (`calendar_list_events`, `calendar_create_event`) | Google Calendar, Outlook, Zoom; Calendly и Cal.com (только список) |
| файлы и документы (`files_search`, `files_read`) | Google Drive, Notion, Confluence |
| задачи (`tasks_list`, `tasks_create`) | Todoist, Jira, Linear, Asana, ClickUp, Trello (только список) |
| контакты (`contacts_search`) | HubSpot, Pipedrive, Zendesk, Intercom, Freshdesk |
| сообщения (`messages_search`, `messages_list_chats`, `messages_read_chat`, `messages_send`) | Slack, Telegram, WhatsApp |

Ограничения сервисов в едином виде: IMAP ищет в одной папке (по умолчанию «Входящие»), Gmail и
Outlook — во всей почте; Todoist отдаёт только открытые задачи, а проект в `tasks_create` пока не
задаётся (Todoist нужен id проекта, а не название); Slack не сообщает число непрочитанных, поэтому
`unread_only` в списке чатов не работает.

## Проверка и лимиты

- `POST /api/v1/accounts/:id/test` проверяет подключение и записывает, чей это аккаунт (адрес почты,
  логин). Хаб делает это и сам раз в сутки.
- Ошибки сервисов приходят ИИ короткими понятными сообщениями: «нет доступа», «не найдено»,
  «превышен лимит, повторите через N секунд». Истёкший OAuth хаб обновляет сам.
- Длинные письма и документы обрезаются (`maxChars`), в ответе тогда есть `truncated` и полный
  размер, чтобы ИИ мог дочитать.
